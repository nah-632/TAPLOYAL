## 1. 🔴 اكتشاف أمني: منفذ CranL الخارجي بلا TLS

محاولة الاتصال بـ`sslmode=require` تفشل حرفيًا:
```
SSL_NOT_SUPPORTED: The server does not support SSL connections
```
⇒ أي اتصال بقاعدة البيانات **من خارج CranL** يمرّ **بنص صريح عبر الإنترنت العام** (كلمة المرور والبيانات معًا).

| السياق | الوضع | الحكم |
|---|---|---|
| التطبيق داخل CranL → `taployal_cadoql` (شبكة داخلية) | لا مرور على الإنترنت العام | ✅ المسار الإنتاجي |
| بيئة التطوير هنا → `<cranl-external-host>:<port>` | **نص صريح** | ⚠️ مقبول **مؤقتًا فقط** لقاعدة تطوير ببيانات مُصنَّعة |

**الإجراءات المتخذة:** التحذير مطبوع في `tools/provision-app-role.mjs` عند `--sslmode disable`، والأمر موثَّق هنا وفي `.env.local`. **يجب إغلاق الوصول الخارجي بعد W7**، وعندها يُبطَل مسار الهجوم أصلًا.

## 2. عيب تصميمي حقيقي انكشف وأُصلح

المحاولة الأولى فشلت بخطأ نوع:
```
Failed query: select "role","merchant_id","is_active" from "users" where "users"."id" = $1
params: rXL1pyAqdDzNxsQDj1kKQIWrmkQ0AXfV
```
**السبب:** Better Auth يولّد معرّفات **نصية عشوائية** افتراضيًا (32 حرفًا)، بينما `users.id` عندنا **`uuid`** — وهو شرط صريح في توجيهك (§3: «UUID Primary Keys»).

**الإصلاح** في `src/identity/better-auth.ts`:
```ts
advanced: { database: { generateId: () => randomUUID() } }
```
⇒ كل مفاتيح المصادقة الأساسية صارت UUID حقيقية، وتشارك الهوية صفّها الشخصي **بنفس المعرّف** بلا جدول ربط.

لو لم أُجرِ هذا الاختبار، لكان العيب قد ظهر لاحقًا في أول تسجيل دخول حقيقي.

## 7. ما لم يُنجَز (صريح)

- ⬜ التحقق من البريد **ببريد حقيقي** وإرساله — الاختبار يضبط `email_verified` في القاعدة محاكيًا ضغط المستخدم على الرابط. الإرسال الفعلي يحتاج مزوّد (CranL Email `connected=false` أو SMTP).
- ⬜ استعادة كلمة المرور — لم تُنفَّذ ولا مُختبَرة.
- ⬜ MFA (TOTP) — الـplugin مُسجَّل والجدول موجود وسياسة الفرض مُختبَرة كوحدة، لكن **تسجيل وتحقّق TOTP لم يُختبرا سلوكيًا**.
- ⬜ CSRF وRate limiting — مُهيَّأة، **غير مُختبَرة**.
- ⬜ اختبارات IDOR عبر HTTP على مسارات التطبيق — تحتاج نشر التطبيق (W7).

## 8. 🔴 حادثة أمنية أثناء العمل — أُبلغ عنها وأُصلحت

**ما حدث:** كُتب `DATABASE_URL` (بكلمة مرور `taployal_app`) في `.env.local`، ثم **نسخه سكربت المزامنة إلى المجلد المشترك** `/var/minis/workspace/taployal/` لأن قائمة الاستثناءات لم تكن تحوي `.env.local`.

**الأثر:** انكشف السرّ في مجلد يراه المالك ويمكن أن تصل إليه جلسات أخرى — خارج المسار المحمي بصلاحيات 600.

**الإجراء المُتَّخذ فورًا:**
1. حُذف الملف من المجلد المشترك (والتحقق بغيابه).
2. أُضيفت إلى `tools/sync-workspace.sh` استثناءات: `.env.local` · `.env` · `.env.*.local` · `.test-build`.
3. **أُديرت (rotated) كلمة المرور** — القديمة صارت غير صالحة تمامًا، فلا قيمة لما انكشف.
4. أُعيد تشغيل الاختبار بقاعدة المفتاح الجديد: **8/8 · 0 فشل**.

**درس مُثبَّت:** أي سكربت مزامنة أو نسخ احتياطي يجب أن يعمل **بقائمة منع (deny-list) للأسرار**، لا بقائمة سماح. أُضيف هذا للقاعدة في سجل المشروع.
